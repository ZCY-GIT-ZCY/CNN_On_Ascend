## 一、昇腾 AI Core 架构说明

### 1.1 内存层次结构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          昇腾 310B1 内存架构                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│                        ┌─────────────────┐                                  │
│                        │   Host (CPU)    │                                  │
│                        │   DDR Memory    │  ← 8GB/16GB LPDDR4X             │
│                        │                 │    带宽: ~25 GB/s              │
│                        └────────┬────────┘                                  │
│                                 │ PCIe                                         │
│                                 ▼                                           │
│                        ┌─────────────────┐                                  │
│                        │   Device (NPU)   │                                  │
│                        │  ┌───────────┐  │                                  │
│                        │  │  L2 Cache │  │  ← ~1MB, 带宽 ~200 GB/s      │
│                        │  └─────┬─────┘  │                                  │
│                        │  ┌─────▼─────┐  │                                  │
│                        │  │  L1 Cache │  │  ← ~256KB, 带宽 ~2 TB/s       │
│                        │  └─────┬─────┘  │                                  │
│                        │  ┌─────▼─────┐  │                                  │
│                        │  │  AI Core  │  │  ← 计算单元                     │
│                        │  └───────────┘  │                                  │
│                        └─────────────────┘                                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1.2 各单元说明

| 单元 | 功能 | 适用算子 | 带宽/性能 |
|:----:|:----:|:--------:|:---------:|
| **Cube** | 矩阵乘法 | Conv2D, GEMM | 1536 INT8 ops/cycle |
| **Vector** | 逐元素运算 | ReLU, Add, BN, Pool | 256 FP32 ops/cycle |
| **Scalar** | 标量计算 | 控制流, 地址计算 | 辅助计算 |
| **MTE1** | L1/L2访问 | 数据加载/保存 | ~200 GB/s |
| **MTE2** | DDR访问 | 数据加载/保存 | ~25 GB/s (最慢) |
| **FixPipe** | 格式转换 | NCHW↔NC1HWC0 | 数据重排 |

## 二、模型结构对比

### 2.1 MobileNetV3-Small

- **深度可分离卷积**: DWConv + PWConv，减少 8-9 倍计算量
- **SE 注意力**: Squeeze-and-Excitation 通道注意力
- **无残差连接**: 串行结构，无 Add 操作

### 2.2 ResNet50

- **标准卷积**: 3×3 卷积核
- **残差连接**: BottleNeck 结构，恒等映射 + Add
- **深度更深**: 50 层，16 个 BottleNeck

## 五、性能指标分析

### 5.1 为什么延迟不能直接对比？

> ⚠️ **重要**: 由于两个模型的参数量、计算量差异巨大（73倍），延迟不能直接作为性能对比的指标。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    参数量与计算量差异                                       │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  MobileNetV3:          ResNet50:              比值:                   │
│  ───────────────      ──────────────          ──────                   │
│  参数量: 2.5M         参数量: 25.6M          1 : 10.2                │
│  FLOPs: 56M           FLOPs: 4.1G            1 : 73                  │
│  延迟: 0.96ms         延迟: 3.81ms           1 : 4.0                 │
│                                                                             │
│  如果用延迟对比: MobileNet 快 4 倍                                      │
│  但 ResNet50 计算量是 MobileNet 的 73 倍！                              │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 5.2 Cube 占比的正确理解

| 指标 | MobileNetV3 | ResNet50 |
|:----:|:-----------:|:--------:|
| **Cube 占比** | 14.0% | 48.9% |
| **DDR 带宽利用率** | **83%** (正常) | **212%** (超载) |

> ⚠️ **注意**: Cube 占比高不代表效率高，**DDR 是否超载才是关键指标**。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    为什么 MobileNet 的 Cube 占比低？                          │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  MobileNetV3 算子分布:                                                 │
│  ───────────────────────                                                  │
│  • Conv2D:     41.4% (Cube)                                            │
│  • MatMulV2:   19.1% (Cube)                                            │
│  • Fusion:     18.1%                                                   │
│  • Vector:     ~13.6%                                                  │
│  • FC:          7.0%                                                   │
│                                                                             │
│  原因:                                                                │
│  • MobileNet 计算量小 (56M FLOPs)，Cube 很快算完                         │
│  • 剩余时间做 MatMul, Vector 等其他操作                                   │
│  • 但 DDR 带宽利用率只有 83%，没有严重瓶颈                               │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    为什么 ResNet50 的 Cube 占比高？                          │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ResNet50 算子分布:                                                    │
│  ─────────────────                                                       │
│  • Conv2D:     93.2% (Cube)                                            │
│  • MatMulV2:    5.1%                                                   │
│  • 其他:        ~1.7%                                                   │
│                                                                             │
│  原因:                                                                │
│  • 几乎全是卷积计算 (标准卷积)                                           │
│  • 计算量大 (4.1G FLOPs)                                                │
│  • 但 DDR 带宽超载 2.1 倍，Cube 在等待数据                              │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 5.4 参数效率对比

| 指标 | 计算公式 | MobileNetV3 | ResNet50 |
|:----:|:--------:|:-----------:|:--------:|

## 六、瓶颈原因分析

### 6.1 DDR 带宽需求分析

**ResNet50**:

| 数据类型 | 大小估算 | 说明 |
|:--------:|:--------:|:-----:|
| 输入图像 | 150 KB | 224×224×3 |
| 权重加载 | 102 MB | 25.6M × 4 bytes |
| 中间特征图 | ~100 MB | 每层输入输出 |
| **总计** | **~202 MB** | |

```
带宽需求: 202 MB / 3.81 ms = 53.0 GB/s
DDR 上限: 25 GB/s
带宽压力比: 53 / 25 = 2.1 倍
```

**MobileNetV3**:

| 数据类型 | 大小估算 | 说明 |
|:--------:|:--------:|:-----:|
| 输入图像 | 150 KB | 224×224×3 |
| 权重加载 | 10 MB | 2.5M × 4 bytes |
| 中间特征图 | ~10 MB | 小特征图 |
| **总计** | **~20 MB** | |

```
带宽需求: 20 MB / 0.96 ms = 20.8 GB/s
DDR 上限: 25 GB/s
带宽压力比: 20.8 / 25 = 0.83 倍 (正常)
```

### 6.2 瓶颈对比

| 瓶颈类型 | MobileNetV3 | ResNet50 |
|:--------:|:-----------:|:--------:|
| DDR 带宽利用率 | **83%** (正常) | **212%** (超载) |
| FixPipe | 中等 (33.3%) | **高 (49.1%)** |
| 主要瓶颈 | 无 | **DDR 带宽** |

## 七、GPU vs 昇腾 NPU 对比

### 7.1 内存架构差异

| 平台 | 内存类型 | 带宽 | 容量 | 权重存放 |

| **RTX 4090** | GDDR6X | 1,008 GB/s | 24 GB | 可一次加载 |
| **A100** | HBM2e | 2,000 GB/s | 40-80 GB | 可一次加载 |


### 7.2 为什么显存足够能降低损耗？

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    权重无法全部缓存到片上                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ResNet50 权重: 100 MB                                                 │
│  ─────────────────────                                                  │
│  昇腾 L2 Cache: ~1 MB (只能存 1%)                                     │
│                                                                             │
│  结果: 每层卷积都需要从 DDR 加载权重                                    │
│                                                                             │
│  GPU 为什么更好:                                                        │
│  ─────────────                                                          │
│  RTX 4090 带宽 1,008 GB/s:                                           │
│  • 3.81ms 内可传输: 1,008 × 0.00381 = 3,840 MB                       │
│  • 完全满足 202MB 需求，绰绰有余                                       │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 八、优化建议

### 8.1 针对 ResNet50

| 优化方向 | 具体措施 | 预期效果 |
|:--------:|:--------:|:--------:|

## 九、核心结论

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        核心结论                                           │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  1. 延迟不能直接对比                                                      │
│     • 两个模型参数量差 10 倍，计算量差 73 倍                              │
│     • 延迟对比没有意义                                                   │
│                                                                             │
│  2. Cube 占比不是效率指标                                                │
│     • MobileNet Cube 占 14% ≠ 效率低                                     │
│     • ResNet50 Cube 占 93% ≠ 效率高                                      │
│                                                                             │
│  3. DDR 带宽利用率才是关键指标                                           │
│     • MobileNetV3: 83% (正常，无瓶颈)                                    │
│     • ResNet50: 212% (超载 2.1 倍，主要瓶颈)                            │
│                                                                             │
│  4. ResNet50 瓶颈在 DDR 带宽                                            │
│     • 带宽需求 53 GB/s，超过 25 GB/s 上限                               │
│     • 权重 100MB 无法全部缓存到片上                                      │
│     • Cube 等待 DDR 数据                                                │
│                                                                             │
│  5. MobileNetV3 几乎没有瓶颈                                             │
│     • 带宽需求 20.8 GB/s，在 25 GB/s 之内                              │
│     • 权重 10MB，Cache 友好                                             │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```
