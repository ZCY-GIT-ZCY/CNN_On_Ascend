## 一、重要说明：时间占比 vs 利用率

> ⚠️ **术语澄清**：msprof 输出的 "utilization" 实际上是 **时间占比 (Time Ratio)**，即：
> 
> ```
> 时间占比 = 该单元执行时间 / 总推理时间 × 100%
> ```
> 
> 这与传统意义上的"硬件利用率"不同，传统利用率 = 实际计算量 / 理论最大计算量

### 指标含义对比

| 指标名称 | 含义 | 数值高表示 |
|:--------:|:----:|:----------:|
| 时间占比 | 该单元占用时间/总时间 | 该单元是瓶颈 |
| 传统利用率 | 实际计算/理论计算 | 资源是否充分利用 |

## 五、瓶颈分析

### 5.1 如何理解时间占比

```
┌─────────────────────────────────────────────────────────────────────────┐
│  "MTE2 80.6%" 的含义                                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  时间轴: 0ms ───────────────────────────────────────► 3.81ms           │
│                                                                         │
│  ResNet50 推理过程中:                                                 │
│  │████████████████████│██│████████████│██│████│████████████████│   │
│  └──── MTE2 80.6% ──┘└──────────┘         └──── Cube 48.9% ──┘    │
│                          ↑                    ↑                        │
│                    其他所有操作              Cube在等MTE                │
│                                                                         │
│  解读:                                                                │
│  • 80.6% 的时间在等待 DDR 数据传输                                    │
│  • Cube 计算单元 48.9% 时间在工作                                     │
│  • 但 Cube 有一半时间在等待 MTE 完成                                  │
│  • Vector 只有 2.3%，说明逐元素操作很少                               │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 5.2 瓶颈判断

| 模型 | 占比最高的单元 | 问题诊断 |
|:----:|:--------------:|:---------|
| MobileNetV3 | MTE2 (44.3%) | DDR带宽中等压力 |
| ResNet50 | MTE2 (80.6%) | **DDR带宽严重瓶颈** |

---

## 六、关键结论

1. **时间占比 ≠ 硬件利用率**
   - 时间占比高 = 该操作占用时间多
   - 可能是瓶颈，也可能是正常的计算需求

2. **ResNet50 的主要问题**
   - MTE2 占 80.6%，说明大量时间在 DDR 数据传输
   - Cube 虽占 48.9%，但有一半时间在等待

3. **优化方向**
   - 减少 DDR 访问次数 (算子融合)
   - 减少数据格式转换 (FixPipe 优化)
