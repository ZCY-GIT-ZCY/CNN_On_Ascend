# ResNet50 Memory 效率分析

**分析时间**: 2026-05-28  
**平台**: Ascend 310B1

---

## 一、问题现象

| 指标 | MobileNetV3 | ResNet50 | 差异 |
|:----:|:-----------:|:--------:|:----:|
| Memory 利用率 | 70.9% | **99.3%** | +28.4% |
| MTE2 (存储) | 44.3% | **80.6%** | +36.3% |
| **FixPipe** | **33.3%** | **49.1%** | +15.8% |
| Cube 利用率 | 14.1% | 48.9% | +34.8% |
| Vector 利用率 | 22.2% | 2.3% | -19.9% |

---

## 二、FixPipe 是什么？

FixPipe (固定管线) 是昇腾 NPU 中处理数据重排的硬件单元，主要负责：
- 特征图格式转换 (如 NCHW ↔ NC1HWC0)
- 数据对齐和填充
- Tensor 重排

---

## 三、FixPipe 高占用的原因

### 3.1 两模型对比

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    FixPipe 对比                                          │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  MobileNetV3: 33.3%                                                   │
│  ├── 深度可分离卷积的数据布局相对简单                                     │
│  └── 中间结果较少                                                      │
│                                                                         │
│  ResNet50: 49.1% (高 15.8%)                                          │
│  ├── 标准卷积产生更大的中间特征图                                       │
│  ├── 残差连接需要数据同步                                              │
│  └── 多层堆叠导致频繁的数据格式转换                                     │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.2 原因分析

ResNet50 的 FixPipe 更高的原因:

1. **更大的特征图**: 56×56, 112×112 的特征图需要更多重排
2. **残差连接**: Add 操作前后可能需要数据对齐
3. **中间结果**: 多层堆叠导致频繁的格式转换
4. **维度匹配**: 残差连接可能需要 1×1 Conv 进行维度匹配

## 四、深层原因分析

### 4.1 残差连接的影响

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    ResNet 残差连接                                       │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│     ┌─────────────────────────────────────────┐                        │
│     │           主路径                         │                        │
│  ───┤  Conv1 ─► BN ─► ReLU ─► Conv2 ─► BN   ├──► Add ─► ReLU        │
│     │                                         │    ↑                     │
│     └─────────────────────────────────────────┘    │                     │
│                                                       │                     │
│     ─────────────────────────────────────────────────┘                     │
│                         恒等映射 (Identity)                              │
│                                                                         │
│  问题:                                                                   │
│  1. 主路径输出和恒等映射需要同尺寸才能相加                                │
│  2. 当尺寸不同时，需要额外的 Conv 进行维度匹配                             │
│  3. 每个 Block 需要等待两部分计算完成才能执行 Add                          │
│  4. Add 操作前后可能触发 FixPipe 进行数据对齐                             │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 4.2 特征图尺寸变化

ResNet50 的特征图变化:

```
Stage      输出尺寸    卷积数量    特征图总大小    FixPipe压力
─────────────────────────────────────────────────────────────────
Conv1      112×112     1个         大              高
Stage1     56×56       3个         极大            极高
Stage2     28×28       4个         大              中
Stage3     14×14       6个         中              中
Stage4     7×7         3个         小              低
```

**问题**: 早期层 (Conv1, Stage1) 的特征图很大，导致:
- 每次卷积需要访问大量数据
- 中间结果缓存压力大
- DDR 带宽成为瓶颈
- FixPipe 需要频繁重排

## 六、优化建议

### 6.1 针对 ResNet50 的优化

| 优化方向 | 具体措施 | 预期效果 |
|:--------:|:--------:|:--------:|
| **算子融合** | Conv+BN+Add+ReLU 融合 | 减少 30-50% Memory 访问 |
| **残差融合** | 将残差连接融合到主路径 | 消除同步等待和 FixPipe |
| **固定管线优化** | 优化特征图布局 | 减少 FixPipe 开销 |
| **渐进式处理** | 减少大特征图的中间结果保存 | 降低 DDR 带宽压力 |

### 6.2 对比 MobileNet 为什么更好

MobileNet 之所以 Memory/FixPipe 效率更高:

1. **深度可分离卷积**: 减少 8-9 倍的卷积操作
2. **无残差连接**: 无需等待和同步，FixPipe 开销小
3. **小特征图优先**: 大部分计算在 7×7, 14×14 上完成
4. **SE 注意力**: 虽然增加一点开销，但整体仍高效

---

## 七、结论

ResNet50 Memory 效率低的**根本原因**:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  1. MTE2 高达 80.6%: 大特征图 (112×112, 56×56) 导致大量数据访问     │
│                                                                         │
│  2. FixPipe 49.1%: 残差连接导致频繁的数据格式转换和对齐                 │
│                                                                         │
│  3. 残差连接同步等待: 流水线停顿，Memory 压力增加                       │
│                                                                         │
│  4. 多层堆叠 (50层): 中间结果累积，DDR 带宽压力                        │
│                                                                         │
│  结果: Memory 总计 99.3%, Cube 仅 48.9%                               │
│        大部分时间在等待而非计算                                          │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**核心矛盾**: ResNet50 的计算密度高，但 Memory/FixPipe 跟不上，导致计算单元等待数据。
